# 云手机远控使用说明

## 1. 架构

项目只控制服务器电脑通过 ADB 连接并在管理页授权的 Android 设备。

- 被控端使用上游 scrcpy-server 4.1 采集 H.264，并接收 scrcpy 标准控制消息。
- 服务端通过独立的 TLS WebSocket 发送 H.264 Annex-B 视频和 Protobuf 控制消息。
- Android 控制端使用 MediaCodec 直接解码到 SurfaceView；MuMu 环境优先使用软件 AVC 解码器。
- 视频拥塞会丢弃整个旧 GOP 并重启媒体采集取得新 IDR，控制 WebSocket 和会话保持连接。
- 当前链路不使用 WebRTC、RTP、DataChannel、PyAV、aiortc 或 device-agent。

## 2. 构建产物

运行 `scripts/build.ps1` 后，产物生成到 `dist`：

| 文件 | 用途 |
| --- | --- |
| `cloudphone-client.apk` | 安装到 Android 控制端 |
| `cloudphone-remote-ime.apk` | 服务端自动部署到被控设备 |
| `scrcpy-server-direct-v4.1` | 服务端通过 ADB 自动推送的上游采集端 |
| `scrcpy-Apache-2.0-LICENSE.txt` | scrcpy Apache 2.0 许可证 |

只需手工安装 `cloudphone-client.apk`。不要把历史 `cloudphone-device-agent.jar` 或 `scrcpy-server-cloudphone-v4.1` 用于新链路。

## 3. 连接被控设备

1. 在被控设备开启“开发者选项”和“USB 调试”。
2. 用 USB 或已受控的 ADB 通道连接服务器电脑。
3. 在设备上接受 RSA 调试授权。
4. 验证状态：

```powershell
adb devices -l
```

设备状态必须是 `device`。`unauthorized` 表示尚未接受授权，`offline` 通常需要重连设备或重启 ADB。

## 4. 启动服务端

可双击根目录的 `启动云手机服务.bat`，也可以运行：

```powershell
Set-Location '<项目目录>'
.\scripts\run-server.ps1
```

服务端监听：

- `0.0.0.0:8443/TCP`：HTTPS API 以及视频、控制 WSS。
- `127.0.0.1:8080/TCP`：本地管理页。

新链路不需要 UDP 媒体端口。`run-server.ps1` 会强制使用 `dist\scrcpy-server-direct-v4.1`，不会因旧 `server.env` 仍引用定制 scrcpy 而回退。

按 `Ctrl+C` 正常停止。服务端会结束媒体采集、取消活动触点，并尝试恢复被控设备原来的输入法。

## 5. 管理页

在服务器电脑打开 `http://127.0.0.1:8080`，使用配置时设置的管理密码登录。

1. 刷新 ADB 设备列表。
2. 设置便于识别的设备别名。
3. 打开授权开关；只有已授权设备会显示在 Android 客户端。
4. 撤销授权会立即结束该设备的活动会话。
5. “重置客户端绑定”会清除控制端 Android Keystore 公钥绑定。

管理页不会提供任意 ADB Shell、文件浏览或服务器电脑桌面控制。

## 6. Android 控制端

安装 `dist\cloudphone-client.apk`。如果控制端也连接在同一台电脑上，请明确指定序列号：

```powershell
adb -s '<控制端序列号>' install -r '.\dist\cloudphone-client.apk'
```

首次打开会完成 nonce、HMAC-SHA256 和 Android Keystore 绑定。进入已授权设备后：

- 画面支持多点触控，黑边不计入远端坐标。
- 返回、首页、多任务和旋转通过独立控制 WebSocket 发送。
- 画质包含自动、1080P、720P、流畅和原画。
- 画质切换会启动新的 scrcpy 媒体采集，但不会重建控制连接。
- 解码冻结只重建 MediaCodec；视频积压只重启媒体采集，两者都不会结束控制会话。

## 7. 远程输入法

会话开始时，服务端会部署 Remote IME，保存原默认输入法并尝试临时切换。标准 Android 输入框可提交中文、英文、Unicode 和编辑器动作。

部分 MuMu Android 15 环境禁止 ADB 启用第三方输入法；这时普通触控与按键控制仍可使用，但 Remote IME 输入栏不可用。游戏自绘输入框绕过 `InputConnection` 时也无法使用 Remote IME。

## 8. 重新配置和构建

生成新的证书、PSK 和客户端地址：

```powershell
.\scripts\configure.ps1 -PublicIp '<固定IP>' -PublicPort 8443
```

已有配置不会被覆盖；只有明确传入 `-Force` 才会更换证书、PSK、客户端绑定信息和管理密码。使用 `-Force` 后必须重新构建并安装客户端。

首次构建前需准备 Python 3.11+、JDK 17–21 和 Android SDK 34，并运行 `.\scripts\bootstrap.ps1`；也可以传入 `-PythonExe`、`-JavaHomePath`、`-AndroidSdkPath` 指定环境。

完整 Release 构建：

```powershell
.\scripts\build.ps1
```

构建脚本会运行 Python 测试、Android JVM 测试、两个 APK 的 Release 构建，以及上游 scrcpy 的测试、Release 和 lint。中文仓库路径会被临时映射到空闲 ASCII 盘符，构建结束后自动解除映射。

旧配置中的 `CLOUDPHONE_WEBRTC_*` 和 `CLOUDPHONE_DEVICE_AGENT_*` 会被忽略。若绕过 `run-server.ps1` 启动，请把 `CLOUDPHONE_SCRCPY_SERVER_PATH` 更新为 `dist\scrcpy-server-direct-v4.1`。不要为了改这一项使用 `configure.ps1 -Force`。

## 9. 公网部署

只需转发并放行公共 HTTPS/WSS TCP 端口，例如 `8443/TCP`。不要向公网开放管理端口 `8080`、ADB `5037/5555` 或其他本地调试端口。

```powershell
New-NetFirewallRule -DisplayName 'CloudPhone HTTPS 8443' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443
```

客户端固定验证证书 SPKI pin。公网 IP 或证书变化后，需要重新配置、构建并安装客户端。

## 10. 故障排查

### 客户端无法连接

- 确认服务端正在运行，控制端可以访问配置的 TCP 端口。
- 确认 APK 与当前证书 pin、客户端 ID 和 PSK 属于同一次配置。
- 检查服务端日志中控制 WSS 和视频 WSS 是否分别连接。

### 管理页没有设备

- 运行 `adb devices -l` 检查状态。
- 处理被控设备上的 USB 调试授权提示。
- 确认数据线支持数据传输，然后在管理页刷新。

### 1080P 或原画停住

新链路会在队列超过帧数、字节数或时间跨度限制时丢弃整个旧 GOP，并仅重启 scrcpy 媒体采集取得新 IDR。控制连接应始终可用。若仍冻结，请同时记录服务端的编码/发送计数和客户端的接收/解码/呈现计数，以区分采集、网络和解码器问题。

### 黑屏

带 `FLAG_SECURE`、DRM 或禁止屏幕捕获的应用可能黑屏。项目不会绕过 Android 安全机制。

## 11. 安全和验收

- HTTPS/WSS 使用证书 SPKI pin。
- 客户端认证使用一次性 challenge、nonce、HMAC-SHA256 和 Android Keystore P-256 签名。
- ADB serial、Shell 参数和本地文件路径不会暴露给 Android 客户端。
- 管理页只监听回环地址。

正式验收时，1080P 和原画应各持续运行至少 15 分钟，并持续制造动态画面和输入。需要同时确认编码、服务端发送、客户端接收、MediaCodec 解码和 Surface 呈现五层计数持续增长；视频恢复期间控制 WSS、服务端进程和会话对象不得退出。
